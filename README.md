# FAGI — Federated Adversarial Graph Intelligence

Code, data loaders, experiments and results for the paper *FAGI: Measuring the Costs of Adversarial Training, Edge Filtering, and Differential Privacy in Graph-Based Threat Detection* (Shahzaib Ejaz, North American University).

FAGI combines four components and measures what each one costs and buys:

| Component | What it does | Where |
|---|---|---|
| Graph construction | API sessions → 12-endpoint call graphs; CICIDS2017 flows → k-NN ego graphs over a reference pool | `fagi/graph/`, `data/cicids2017.py` |
| Detector | 2-layer GraphSAGE (64/32, mean aggregation), linear head | `fagi/model/dense.py` |
| Robustness | GNNGuard-style edge pruning (cosine τ = 0.15) and PGD adversarial training (L∞, K = 10) | `fagi/model/dense.py`, `fagi/training.py` |
| Privacy | DP-SGD: per-example clipping, Gaussian noise, Poisson sampling, Rényi-DP accounting (Opacus); FedAvg across organizations | `fagi/privacy/dp_sgd.py`, `experiments/exp4_federated.py` |

All results in the paper are in [`experiments/results/paper_results.json`](experiments/results/paper_results.json) and summarized in [`dashboard.html`](dashboard.html), a single page with the results tables, a threshold-switchable robustness chart, CSV export and print/PDF. Both are generated by scripts; nothing is typed in by hand. Rebuild the dashboard with `python scripts/build_dashboard.py`.

**Live dashboard:** https://shahzaib-ejaz.github.io/FAGI/ . It is rebuilt from `paper_results.json` on every push that changes the results (workflow `dashboard-pages`), so it always matches the repository.

## Main findings

Worst-case recall on attacked malicious flows (CICIDS2017, attack budget ε_adv = 0.5, 5 folds × 3 seeds) with every model's threshold set to a 1% false-positive rate on benign test flows. The attacks minimize each model's score: mimicry, transfer, a retrieval-aware neighborhood attack, white-box margin attacks, and score-based random search (`experiments/strong_attacks.py`).

| Model | Recall |
|---|---|
| FAGI without DP | 28.6% |
| k-NN vote over the reference pool | 26.2% |
| FAGI (ε = 2.90) | 14.1% |
| GNN, no defenses | 11.8% |
| All MLP variants, random forest, 1D-CNN | 0.0% |

* Adversarial training is what keeps the graph detector working under attack. DP-SGD gives most of that back.
* GNNGuard has no measurable effect, and a k-NN vote that needs no training matches FAGI without DP and beats FAGI.
* The random forest is the most accurate clean detector, but a query attack on its scores leaves 65.4% detected at ε_adv = 0.1 at the matched rate (21.0% at its default threshold) and none at 0.5.
* Controls (seed 0): DP-SGD's robustness cost is the noise, not clipping or sampling, and retuning the training for privacy does not recover it at ε_adv = 0.5. Models trained only on the public reference pool, with no private record, match or beat FAGI, even when the pool is a ninth the size of the private set.
* At each model's default threshold the ranking looks different, because the models flag very different amounts of benign traffic. Compare models at a matched false-positive rate.
* On a file-order split (train on the first 70% of each day file, test on the rest), no model keeps more than 2.8% at this budget.

## Quick start

```python
import sys; sys.path.insert(0, "data/synthetic")
from generator import generate_dataset
from fagi import FAGIDetector

sessions = generate_dataset(seed=1)
det = FAGIDetector(dp_sigma=1.1, dp_clip_norm=1.0, dp_delta=1e-6, pgd_epsilon=0.1)
det.fit(sessions, epochs=30)          # prints the computed epsilon
print(det.epsilon)                    # computed by the RDP accountant, not a setting
pred = det.predict(sessions, adversarial=True)
```

Pass `feature_scale=` (per-feature scales from public data) to keep the scaler's statistics out of the private data; otherwise they are fit on the training sessions and fall outside the DP guarantee. The privacy budget is an output, not an input: `FAGIDetector` takes the noise multiplier σ, clip norm and δ, and reports the ε that the accountant computes for the sampling rate and number of steps actually used.

DP noise is drawn from a seeded `torch.Generator` so that experiments are reproducible. That is right for research and wrong for deployment: a released model needs noise from a cryptographically secure generator (as in Opacus' `secure_mode`), otherwise an attacker who learns the seed can subtract the noise.

## Reproducing the paper

```bash
bash scripts/run_all.sh
```

This regenerates both synthetic datasets, runs every experiment, writes `experiments/results/*.json`, builds `paper_results.json`, the figures in `figures/`, and `dashboard.html`. Expected runtime is about 19 hours on a 2-core CPU, about 10 of them for the score-minimizing attack suite. The published results were produced by running the same commands in chunks (per seed, then the aggregators), which is equivalent because every stage reads the shared cache. CICIDS2017 models are cached per (model, fold, seed) under `experiments/results/cache/`, keyed by a hash of the configuration and the core source files, so an interrupted run resumes where it stopped.

| Script | What it produces |
|---|---|
| `experiments/cicids_compute.py` | Trains and attacks every CICIDS2017 model (cached, including weights); `--protocol temporal` for the time split |
| `experiments/exp1_cicids_benchmark.py` | Clean accuracy, FPR, per-class recall with Wilson intervals, worst-case attack recall |
| `experiments/exp3_adversarial_robustness.py` | Attack-budget sweep, per-attack breakdown, 100-step check; random edge injection on synthetic data |
| `experiments/ablation.py` | Component ablation, σ sweep (privacy–utility), membership inference with an overfit positive control |
| `experiments/mia_canary.py` | Canary audit: 200 label-flipped private flows per fold, half included; AUC with bootstrap CI and an empirical ε lower bound |
| `experiments/exp5_temporal.py` | Temporal split: the earlier 70% of each day file trains, the later 30% tests |
| `experiments/robust_checks.py` | Worst-case recall at matched false-positive rates (0.5%, 1%, 2%; test- and pool-calibrated thresholds) for the CV, ablation and temporal models; adaptive-PGD restart curve |
| `experiments/exp2_api_native.py` | Synthetic API sessions: all attacks, lateral movement, SQL injection; payload-feature ablation |
| `experiments/exp4_federated.py` | Held-out organization, FedAvg with and without client-side DP-SGD, ε-matched centralized DP, membership inference |
| `experiments/attack_checks.py` | Longer random search, a joint graph attack, a certified lower bound for the k-NN vote, per-label recall, tie-breaking spread |
| `experiments/unsw_benchmark.py` | The main comparison on UNSW-NB15 (same sampling, pool split, models, attack suite and matched-FPR evaluation) |
| `experiments/extra_controls.py` | Clipping-only and privacy-tuned DP-SGD, models trained on the pool alone, a 10% pool, pool overlap (`--parts` runs a subset) |

### After rerunning an experiment

`run_all.sh` rebuilds everything. If you rerun only some experiments, propagate their new results with:

```bash
bash scripts/refresh.sh
```

This merges the results into `paper_results.json`, regenerates the figures, rebuilds `dashboard.html` and rebuilds the paper (which stops and names any claim a new result no longer supports). It does not rerun experiments. Commit the regenerated files afterwards. The GitHub workflow `results-in-sync` fails if the committed `dashboard.html` does not match `paper_results.json`, or if the paper's claims no longer hold.

### Building the paper

`run_all.sh` stops at `paper_results.json`, the figures and the dashboard. The paper is built separately from those files:

```bash
cd paper && npm install && node build_paper.js    # writes paper/out/FAGI.docx
```

The LaTeX version for TMLR (named and anonymous) uses the same builder. Put `tmlr.sty`, `tmlr.bst` and `fancyhdr.sty` from the [TMLR style files](https://github.com/JmlrOrg/tmlr-style-file) in `paper/tmlr-style/`, then:

```bash
cd paper && bash build_tex.sh    # writes paper/out/tex/FAGI.tex and paper/out/tex_anon/FAGI.tex (and PDFs if pdflatex is installed)
```

Every number in the paper is read from `paper_results.json`, so rerunning the experiments and rebuilding updates the tables and text. Each directional statement in the paper is checked against the results; if a rerun changes one, the build stops and names it. See [`paper/README.md`](paper/README.md).

### Evaluation protocol in brief

* **CICIDS2017**: all 8 day files, cleaned (non-finite rows, exact duplicates, constant and duplicated columns removed; mis-encoded Web Attack labels fixed), then a stratified sample of up to 3,000 flows per attack label plus an equal number of benign flows. 5-fold CV stratified on the original label, 3 seeds per fold. Each training fold is split into a **private training set** (what DP protects) and a **reference pool** that supplies graph neighbors at training and inference time; no private record ever appears in another record's graph.
* **Attacks** target 2,000 malicious test flows per fold (the same flows for every model); benign flows are left unperturbed. Every model is attacked through its own inference path (neighbor retrieval included). The stored attacks from training time are best-of-32 benign mimicry, white-box PGD (adaptive PGD that re-retrieves neighbors at every step with 2 restarts, plus PGD followed by re-retrieval, for graph models), and transfer of the MLP's PGD and the GNN's adaptive examples. `experiments/strong_attacks.py` then minimizes each model's score from the cached models: a retrieval-aware neighborhood attack that pulls a flow toward benign pool flows and away from malicious ones, logit-margin gradient attacks (a soft vote for k-NN), transfer of the best examples between five source models, and score-based random search (2,000 queries per flow for the random forest). Each flow keeps its lowest score, so the same examples serve every threshold. A flow counts as detected only if it survives every attack. PGD on a fixed neighborhood is reported separately and excluded from the worst case. Paired tests use the five fold means (seeds averaged), with win counts.
* **Temporal protocol**: within each day file, rows follow flow completion order; the earlier 70% (split into private set and pool) trains and the later 30% tests.
* **Privacy**: δ = 10⁻⁶. Hyperparameters were fixed in advance and not tuned on the evaluation data.
* **Synthetic API sessions**: `data/synthetic/generator.py` (original) and `--difficulty hard`, where some benign users send admin, export or SQL-like requests and half of attack calls carry ordinary payloads. Features are divided by fixed per-feature scales computed once from a public calibration sample (the original generator with seed 7, never used for evaluation, and applied to both the original and the hard data), so no statistics are fit on private or test data.

## Datasets

**CICIDS2017** — download `MachineLearningCSV.zip` from the [Canadian Institute for Cybersecurity](https://www.unb.ca/cic/datasets/ids-2017.html) and extract the eight CSV files into `data/cicids2017/`. See [`data/README.md`](data/README.md) for the expected files, checksums and the cleaning steps.

**UNSW-NB15** — download `UNSW_NB15_training-set.csv` and `UNSW_NB15_testing-set.csv` from the "Training and Testing Sets" folder of the [UNSW-NB15 page](https://research.unsw.edu.au/projects/unsw-nb15-dataset) into `data/unsw_nb15/`. `data/unsw_nb15.py` checks the row counts and records the SHA-256 checksums; `experiments/unsw_benchmark.py` repeats the main comparison on it.

**Synthetic API sessions** — `python data/synthetic/generator.py` writes `data/synthetic/sessions_final.json` (seed 42, 4,000 sessions, 5 organizations); add `--difficulty hard --output data/synthetic/sessions_hard.json` for the hard variant.

## Provenance of the synthetic results

`exp2.json`, `exp2_hard.json` and `ablation_hard.json` were produced before later changes to `fagi/training.py` (optional optimizer-state arguments) and `fagi/federated/server.py` (filter off by default). Both changes keep the old behavior at their defaults, which is how those experiments call them, and rerunning the three scripts reproduces every number in them exactly. The graph-structure attack in `exp3.json` is computed on the hard generator (`--api_data data/synthetic/sessions_hard.json`).

## Changes from the first version of this repository

The first version reported results (for example 74.4% vs 67.2% under PGD, ε = 2.0, 78.6% membership-inference success) that could not be reproduced from the code: the CICIDS2017 loader was missing, the privacy noise in the experiment scripts was σ ≈ 0.004 rather than 1.1, ε was asserted rather than computed, and the "LLM" payload feature was a keyword count. All results were regenerated from scratch with the code in this repository. The keyword payload score is described as such; the DistilBERT embedder in `fagi/utils/embeddings.py` is not used by any experiment.
